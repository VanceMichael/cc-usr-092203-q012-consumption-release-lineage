# 消费促进成效归因

评估促消费措施带来的真实增量、成本和持续影响。仅凭同比上升无法说明本地补贴带来了新增需求——季节、价格和全国性平台活动都会推高同比，因此本服务用可解释的对照规则估计增量，并让每个结论可重放、可审计。

## 资料约定

`contracts/domain.schema.json` 描述共享资料的字段结构，`fixtures/domain.json` 提供不含真实个人信息的业务样例。读取模块只校验资料边界，不预先实现业务流程。

当前资料反映以下领域事实：

- 消费数据同时覆盖商品、服务和县乡市场
- 不同类别使用不同统计范围与同比口径
- 部分趋势来自重点平台商务大数据

## 服务结构

`fixtures/scenario.json` 是一个完整的合成样例（云州市智能家电消费券，临江县对照），覆盖全部修正情形。数据流：

1. **事件**（`src/events.js`）：活动、适用人群、商户、地区、品类、预算、曝光、领取、核销、退货与消费统计，每条记录都带业务时间边界（`valid_from`/`valid_to`）与系统记录时间（`recorded_at`）。事件库只追加，不改写。
2. **基线冻结**（`src/baseline.js`）：政策开始前冻结基线快照并固化哈希；事后补录或改动政策前数据会导致校验失败。
3. **增量估计**（`src/estimate.js`、`src/metrics.js`）：双重差分——指定对照地区，或以分阶段实施中尚未覆盖的地区为对照。增量、持续消费、挤出效应与单位成本都带 95% 不确定区间，假设以文字列明。
4. **修正**（`src/corrections.js`）：跨活动重复领取、商户迁址、统计分类变化、迟到退款、异常刷单，全部以追加的修正记录进入计算，并标注理由。迟到退款由报告的 `as_of` 截止自然纳入对应版本。修正只产生新报告版本，旧报告原样保留。
5. **报告与重放**（`src/report.js`）：报告内容 = 纯函数(事件 as_of 视图, 修正集, 配置, 基线)，内容哈希随报告保存。审计时用相同输入重算比对哈希即可重放任何结论；`compareReports` 按单位成本排序比较不同措施。
6. **授权环境**（`src/environment.js`）：平台明细（到人级的领取、核销）只能在授权环境内处理；报告生成也必须授权，对外只输出汇总与估计。
7. **公开说明**（`src/disclosure.js`）：明确区分观察事实（直接来自记录，不带区间）与估计（带方法、假设与不确定范围）。

刷单识别（`src/fraud.js`）只使用可解释规则（同人同日集中核销、商户核销突增）产出候选线索，是否剔除须经人工确认后以 `fraud_flag` 修正记录进入归因。

记录结构约定见 `contracts/events.schema.json`，代码侧由 `src/events.js` 与 `src/corrections.js` 执行校验。

## 本地校验

运行 `npm test` 可确认：样例资料可读取；事件时间边界完整；基线冻结防篡改；增量、持续消费与挤出效应的估计数值与区间正确；五类修正各自生效且旧报告保留；任意版本报告可重放、篡改输入即不可复算；未授权环境无法接触平台明细；公开说明中事实与估计严格分离。仓库不保存账号、密钥、连接串或真实身份资料。
