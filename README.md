# 消费促进成效归因

评估促消费措施带来的真实增量、成本和持续影响。仅凭同比上升无法说明补贴带来了新增需求——季节、价格和全国性平台活动都会推高同比，因此本仓库把归因建立在对照与可重放的资料边界上。

## 资料约定

`contracts/domain.schema.json` 描述共享资料的字段结构，`fixtures/domain.json` 提供不含真实个人信息的业务样例。读取模块只校验资料边界，不预先实现业务流程。

`fixtures/campaign.json`、`fixtures/events.json`、`fixtures/corrections.json` 提供一次补贴活动的样例：活动登记、曝光/领取/核销/退货事件，以及修正记录。仓库不保存账号、密钥、连接串或真实身份资料。

## 模块

- `src/time.js` — 统一的时间边界（左闭右开），活动、人群、商户、地区、品类、预算、曝光、领取、核销、退货各有窗口；报告按记录时间取知识截止
- `src/baseline.js` — 基线必须在政策开始前冻结，冻结后任何修改都会抛错
- `src/estimate.js` — 可解释的增量估计：优先对照组双重差分；没有对照组时退回分阶段规则，并标注更低置信度
- `src/corrections.js` — 跨活动重复领取、商户迁址、统计分类变化、异常刷单的修正；迟到退款按记录时间进入后续版本
- `src/report.js` — 追加式报告：修正产生新版本，旧报告连同固定输入一起保留，审计可重放任何结论并核对摘要
- `src/access.js` — 平台明细属于受限资料，只能在授权环境处理
- `src/digest.js` / `src/stats.js` — 摘要与统计基础

## 归因口径

- 观察事实与估计分开表达；估计一律给出不确定范围，不发布单一的同比数字
- 决策者可以比较各措施的单位成本（补贴净支出 / 新增消费）、活动后的持续消费和非补贴品类的挤出效应
- 统计分类变化按报告固定的分类版本生效，旧报告用旧版本重放时数字不变
- 报告输入含受限平台明细时，整个计算必须在授权环境进行

## 本地校验

运行 `npm test` 可确认样例资料能够被读取，领域标识、版本、参与方、事实和约束均保持完整，并验证基线冻结、增量估计、修正、报告重放与授权边界的行为。
